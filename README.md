# gauss_app — a step-by-step Gaussian-elimination calculator as an Android app (and a PWA)

Row reduction the way it is taught in a first linear-algebra course: only the three elementary
row operations, written `L₂ → L₂ − 2·L₁`, every step shown with the pivot and the changed rows
highlighted, exact arithmetic over ℚ and ℂ (fractions and complex numbers, never floats), the
echelon and canonical forms, and the solution set — one, none, or infinitely many with parameters
`α, β, …` — checked by substituting it back. A practice mode hides the steps and reveals them one
at a time. Nothing leaves the device: the app has no permissions and no network.

It started as a command-line checker (`reference/gauss.py`) for a university course; the app is a
JavaScript port of that engine, verified against it (see below).

```
web/         the app itself: index.html, style.css, app.js (the page), engine.js (the mathematics)
             + manifest.webmanifest, sw.js, icons/   → also works as an installable PWA
android/     a WebView wrapper: AndroidManifest.xml, MainActivity.java, res/   (no Gradle, no AndroidX)
reference/   the Python engine the port is checked against: gauss.py (CLI), gauss_gui.py, test_gauss.py
tools/       setup-toolchain.sh · build-apk.sh · make-icons.sh · golden.py
tests/       golden.json (388 cases generated by the Python engine) · test_engine.js
build/       gauss.apk after a build (not committed)
```

## The engine is a port, and the port is verified

`web/engine.js` is a line-by-line port of `reference/gauss.py` + `gauss_gui.analyse()` to
JavaScript, with BigInt rationals instead of sympy. It is **not** trusted on its own:
`tools/golden.py` runs 388 inputs through the Python engine (textbook examples, every edge case,
300 random real and complex systems, 27 inputs that must be rejected) and records the full output;
`tests/test_engine.js` then requires the JS engine to reproduce every step label, matrix entry and
solution string exactly.

```
python3 -I tools/golden.py        # regenerate the corpus after any change to the Python engine (needs sympy)
node tests/test_engine.js         # 388 of 388 must match
python3 -I reference/test_gauss.py   # the Python engine's own tests (lecture examples + 300 random systems vs sympy)
```

The command-line tool itself: `python3 reference/gauss.py "x + 2y + 3z = 13; 2x + y + z = 8; 5x + 2z = 16"`.

## Build the APK

```
tools/setup-toolchain.sh          # once: JDK 17 (if the system java is older), build-tools 35, platform 34 → ~/android-toolchain
tools/build-apk.sh                # → build/gauss.apk, signed with a debug key it generates on first use
adb install -r build/gauss.apk
```

The build is plain command-line tools, no Gradle: `aapt2` → `javac` → `d8` → `zipalign` →
`apksigner`. `VERSION_CODE=2 VERSION_NAME=1.1 tools/build-apk.sh` bumps the version. Use
build-tools 35 or newer with a modern JDK — the `d8` in build-tools 34 crashes on class files from
JDK 21+ (`NullPointerException … String.length()`), which is why the setup script installs 35.

## The PWA

Serve `web/` over http(s) — `python3 -m http.server -d web 8080` is enough locally — open it on
the phone and choose *Add to Home screen*. `sw.js` caches the files, so it works offline afterwards.
Bump `CACHE` in `sw.js` whenever a file changes.

## Installing a release APK

Releases carry `gauss-<version>.apk` with its SHA-256. Android will ask you to allow installs from
this source. An update installs over the previous version only if it was signed with the same key,
so check the signer before trusting a build:

```
apksigner verify --print-certs gauss-1.2.apk | grep 'SHA-256'
```

The release key's certificate fingerprint, from 1.2 on (1.1 was signed with a throwaway debug key,
so 1.2 has to be installed after uninstalling 1.1):


## Signing

`tools/build-apk.sh` signs with a local debug key (`android/debug.keystore`, generated on first
use, git-ignored) — fine for your own phone. `tools/build-apk.sh --release` signs with the release
key, created once by `tools/make-release-key.sh` **in your own terminal**: keytool asks for the
passphrase with hidden input, and apksigner asks for it again at every release build (or reads
`GAUSS_KS_PASS` from your shell). The passphrase lives in your password manager and nowhere else;
the keystore (`~/keys/gauss-app-release.jks`) is never committed and needs an encrypted backup
that survives the machine. Lose it and updates become reinstalls; leak it and anyone can ship
"updates" to your users.

## Limits, the same as the desktop tool

At most 10 rows and 10 columns; powers up to a two-digit exponent, not chained; systems with a
parameter (`m`) are refused — the case split is a by-hand skill, substitute a value to check a case.
